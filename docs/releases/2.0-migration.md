# Migrating To IRPlayer 2.0

IRPlayer 2.0 adds a Swift-first facade while keeping the 1.x entry points as a
migration layer.

2.0 is a new framework ABI generation. Source-compatible 1.x entry points remain
available, but binary framework consumers must rebuild against IRPlayer 2.0.

## Player Construction

Before:

```swift
let player = IRPlayerImp.player()
player.playableBufferInterval = 2
player.volume = 1
```

After:

```swift
let player = IRPlayer(configuration: IRPlayerConfiguration(
    playableBufferInterval: 2,
    volume: 1
))
```

`IRPlayer` is the preferred Swift name. It maps to the same Objective-C-compatible
facade used by `IRPlayerImp`.

## Loading Media

Before:

```swift
player.setRequestHeaderFields(headers)
player.decoder = IRPlayerDecoder.FFmpegDecoder()
player.replaceVideoWithURL(contentURL: url as NSURL, videoType: .vr)
player.play()
```

After:

```swift
player.load(IRMediaSource(
    url: url,
    headers: headers,
    videoType: .vr,
    backendPreference: .ffmpeg
), autoplay: true)
```

`IRMediaSource` makes one load atomic: URL, headers, presentation, custom input,
and backend preference are applied together.

Any non-empty `headers` dictionary requires the FFmpeg backend. Public
AVFoundation APIs do not reliably propagate custom headers to every HLS
playlist and segment request. Automatic and legacy header-based loads therefore
select FFmpeg; explicitly forcing `.avFoundation` for such a source fails with
`IRPlayer.Load` code `3`.

A source without a URL does not create a backend. It publishes a typed
`.failure` event (and the legacy error notification) with the `IRPlayer.Load`
error domain. Use `stop()` when the intent is to clear playback.

`IRPlayer.Load` uses distinct codes: `1` for a missing URL, `2` when the
resolved backend cannot be constructed, `3` for a source explicitly forced to
an incompatible AVFoundation backend, and `4` when automatic resolution finds
no supported backend.

## Observing Playback

Before:

```swift
player.registerPlayerNotification(
    target: self,
    stateAction: #selector(stateChanged(_:)),
    progressAction: #selector(progressChanged(_:)),
    playableAction: #selector(playableChanged(_:)),
    errorAction: #selector(playbackFailed(_:))
)
```

After:

```swift
observation = player.observeEvents { event in
    switch event {
    case .stateChanged(_, let current):
        updateState(current)
    case .progress(let time):
        updateProgress(time.current, duration: time.total)
    case .playable(let time):
        updatePlayableTime(time.current)
    case .failure(let error):
        show(error.error)
    }
}
```

Retain the observation token. Events are serialized onto the main thread. The
legacy notifications are emitted from the same event source.

## Stopping And Replacing

- `load(_:)` replaces the current backend deterministically.
- `stop()` releases both cached backend sessions and clears the active source.
- `activeBackend`, `state`, `progress`, `duration`, `playableTime`, and
  `isSeeking` provide a read-only playback snapshot.

Direct changes to `volume` and `playableBufferInterval` use the same validation
as `IRPlayerConfiguration`: volume is clamped to `0...1`, negative buffer
intervals become `0`, and non-finite values fall back to safe defaults.

## Custom RGB Frames

RGB frames now publish dimensions, pixel format, row stride, and bytes as one
validated immutable generation. The former initializer was ambiguous: UIKit
treated its data as RGB24 while Metal treated the same bytes as BGRA32.

Before:

```swift
let frame = IRVideoFrameRGB(
    linesize: UInt(bytesPerRow),
    rgb: bytes
)
frame.width = width
frame.height = height
```

After:

```swift
guard let frame = IRVideoFrameRGB(
    width: width,
    height: height,
    pixelFormat: .bgra32,
    bytesPerRow: bytesPerRow,
    data: bytes
) else {
    return
}
```

Use `.rgb24` for three-byte red/green/blue input and `.bgra32` for four-byte
blue/green/red/premultiplied-alpha input. Padded rows are supported when
`bytesPerRow` covers the format's minimum row size.

For a generic custom `IRFFVideoFrame`, replace separate width and height
assignments with one atomic call:

```swift
frame.setDimensions(width: width, height: height)
```

## Custom Video Decoding

Custom packet callbacks now receive immutable Swift values that are safe to
retain or send to asynchronous work. The former callback exposed a borrowed
`AVPacket` payload and the format session's mutable `AVCodecContext` pointer;
both became invalid outside the synchronous callback.

Before:

```swift
override func videoDecoder(
    _ decoder: IRFFVideoDecoderInfo,
    decodeFrame packet: AVPacket
) -> IRFFVideoFrame? {
    decodeLater(
        packet.data,
        codecContext: decoder.codecContext
    )
    return nil
}
```

After:

```swift
override func shouldHandle(
    _ decoder: IRFFVideoDecoderInfo,
    packet: IRFFVideoPacketDescriptor
) -> Bool {
    true
}

override func videoDecoder(
    _ decoder: IRFFVideoDecoderInfo,
    decodeFrame packet: IRFFCompressedVideoPacket,
    completion: IRFFCustomVideoDecodeCompletion
) -> IRFFCustomVideoDecodeOutcome {
    Task { [completion] in
        let frame = await decode(
            packet.data,
            codec: decoder.codec
        )
        completion.send(videoFrame: frame)
    }
    return .deferred
}
```

`IRFFCompressedVideoPacket` owns its payload and side-data bytes. Raw PTS/DTS
ticks, duration, flags, stream index, and source position remain available.
`IRFFVideoCodecDescriptor` owns codec extradata and publishes immutable codec,
geometry, pixel-format, profile, level, and bitrate fields. Timestamp ticks use
`IRFFVideoDecoderInfo.timebase`.

Packet routing is now explicitly opt-in. Override
`shouldHandle(_:packet:)`, whose `IRFFVideoPacketDescriptor` contains only
allocation-free metadata, and return `true` only for packets the custom decoder
will consume. IRPlayer copies the payload and side data into
`IRFFCompressedVideoPacket` only after that decision. The base
`IRFFVideoInput` implementation returns `false` from `shouldHandle` and
`.dropped`
from `videoDecoder`; subclasses relying on the former implicit interception
must add the override. Once a custom decoder opts in, its typed outcome is
authoritative and never falls back to FFmpeg or VideoToolbox. Use
`.frame(frame)` for synchronous output, `.dropped` for intentional no-output,
`.failed(error)` for terminal failure, or `.deferred` after retaining the
supplied one-shot completion. Resolve deferred work with `send(videoFrame:)`,
`drop()`, or `fail(_:)`. An unretained completion auto-drops; seek and stop
invalidate pending completions, and late or duplicate frames are rejected and
reclaimed. If IRPlayer cannot make the accepted packet's owned copy, decoding
fails terminally instead of retrying it through another decoder.

`IRFFVideoDecoderInfo.maximumDecodeDuration` is the built-in decoder's
buffered-output backpressure threshold. It is not a timeout for custom work:
every deferred completion must resolve, be released for automatic drop, or be
invalidated by seek, stop, or a terminal decode error.

Choose `IRFFVideoInput.OutputType` in the initializer; `outputType` is now
read-only. The `videoOutput` binding is synchronized and weak, so the active
player/display session remains its owner while asynchronous work may read the
binding safely. Direct frame injection is bounded and non-blocking: use
`IRFFVideoInput.trySend(videoFrame:)` to observe admission. A `false` result
means IRPlayer rejected and reclaimed the frame because the session changed or
its output queue was full. Deferred packet completions reserve bounded output
capacity and delay EOF only until the token resolves, deinitializes, or is
invalidated by seek/stop.

Internally, active decode work is generation-owned. A seek advances the
generation and cancels old deferred work. A same-generation flush is accepted
only while the decoder worker is idle; an active-worker request returns
`false` without changing packet, frame, codec, or EOF state.

## Backend Selection

Use `IRPlaybackBackendPreference.automatic` unless the media source requires a
specific implementation. Source-level selection avoids mutating global decoder
rules between loads.

Automatic selection uses FFmpeg for custom request headers, custom video input,
and presentation types outside AVFoundation's supported capability set.

## Objective-C

The existing `IRPlayerImp`, `NSURL`, selector notification, and render-mode APIs
remain Objective-C compatible. The value-based source/configuration/event API is
Swift-first and marked non-Objective-C where necessary.

Objective-C replacement uses
`replaceVideoWithURL:videoType:`. The custom `IRFFVideoInput` overload is
Swift-only. `IRFFPlayer` is an internal backend rather than a public
Objective-C class; applications should control playback through `IRPlayerImp`.
