# IRPlayer-swift 2.0

## Highlights

- Adds the Swift-first `IRPlayer` facade with typed media sources,
  configuration, backend selection, observations, and playback events.
- Reworks AVFoundation and FFmpeg into serialized, generation-owned runtime
  sessions with bounded custom-frame and deferred-decode admission.
- Makes decoded YUV and custom RGB payloads immutable value generations with
  explicit ownership across CPU conversion, Metal upload, and GPU completion.
- Hardens the Metal renderer across 2D, VR, fisheye, fish2pano, distortion,
  and multi-view paths, including RGB mesh rendering and package-safe shader
  resource loading.
- Removes unused `libavdevice` and `libavfilter` link dependencies; the package
  now consumes only codec, format, utility, resample, and scale FFmpeg
  frameworks.
- Expands regression coverage across player/backend lifecycles, decode
  admission, audio, rendering, transforms, snapshots, and public API values.

## Compatibility

- Swift Package Manager remains the supported installation path.
- The package still declares iOS 15+ support in `Package.swift`.
- 2.0 is a new framework ABI generation. Binary framework consumers must
  rebuild against 2.0.
- The 1.x `IRPlayerImp`, URL replacement, and selector-notification entry
  points remain as a source migration layer.
- Custom RGB construction and custom packet-decoding callbacks now use
  validated immutable values. Integrations using the former pointer-based or
  ambiguous byte-layout APIs must migrate; custom video-input `outputType` is
  now fixed at initialization and read-only afterward.
- See [Migrating To IRPlayer 2.0](2.0-migration.md) for API mappings and
  ownership rules.
