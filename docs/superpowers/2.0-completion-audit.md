# IRPlayer 2.0 Completion Audit

Updated: 2026-07-24

## Current Status

The public 2.0 playback architecture, typed events, serialized backend
coordinator, player facade runtime owners, render-state boundaries, decoder
runtime-state hardening, FFmpeg session resource ownership, AVFoundation
session ownership, and Core Audio output session ownership are implemented
and verified. The display runtime now also has explicit render-executor,
Metal-surface, frame-submission, snapshot, and AVPlayer-layer owners. FFmpeg
decoded-audio consumption is isolated from the player facade. The FFmpeg
backend now has a serialized runtime, explicit state and decoder-generation
owners, exactly-once generation-fenced seeks, coherent snapshots, and an
isolated main-thread presentation adapter. The repository is releasable at
each completed slice, but the whole-project modernization requested for 2.0
is not yet complete.

## Completed Boundaries

- Typed media source, configuration, playback events, and observation tokens.
- Backend protocol and coordinator separating the facade from AVFoundation and
  FFmpeg implementations.
- Explicit player lifecycle state.
- Render state/coordinator and render-mode configuration extraction.
- FFmpeg read/display decision helpers.
- Synchronized FFmpeg decoder session state with atomic seek and idempotent
  close semantics.
- Thread-safe FFmpeg bootstrap, packet/frame queue accounting, and video-decoder
  worker state.
- Explicit FFmpeg decoder-session ownership of operations, format context, and
  audio/video decoders, including resource leases and deterministic teardown.
- Duplicate/post-close open rejection and opening-phase resource publication
  fencing.
- Explicit AVFoundation session ownership of the asset, item, player, output,
  observations, notification, and periodic-time token.
- AVFoundation generation tokens and resource leases that reject stale asset,
  seek, retry, observation, and output work across replacement.
- Silent AVFoundation close and deterministic repeatable reset.
- Real `AVPlayerLayer` attachment for normal playback, with VR isolated to the
  video-output/display-link/Metal presentation path.
- AVPlayer command, lifecycle, presentation, track, and resource-owner
  responsibilities split into focused implementation files.
- Explicit Core Audio graph session with serialized lifecycle phases and
  complete-generation publication.
- Injectable Core Audio driver with exact cleanup for every partially built
  graph failure.
- Persistent real-time render context with non-blocking admission, deterministic
  silence, buffer/layout validation, channel mapping, Int16 clipping, and
  callback teardown fencing.
- Synchronized audio event routing with weak handler ownership and exact
  observer-token cleanup.
- Dedicated FFmpeg audio renderer with fenced frame consumption and output
  shutdown before decoder close.
- Non-waiting decoded-audio dequeue so empty or concurrently flushed queues
  yield silence instead of polling the audio callback.
- Reentrant-safe FFPlayer execution shared by commands, playback/time state,
  decoder events, audio sequencing, reset, and close.
- Explicit FFPlayer decoder-generation ownership with per-generation delegate
  bridges, complete-before-open publication, stale/unknown callback rejection,
  detached output/source links, and terminal close fencing.
- Exactly-once generation-owned FFPlayer seek tickets, including deterministic
  cancellation on reset/replacement and `false` completion without a decoder.
- Coherent FFmpeg backend snapshots whose seeking value follows the active
  decoder rather than a detached stored flag.
- Silent FFPlayer deinit, repeatable reset, lifecycle-fenced failure delivery,
  and main-thread presentation mapping for every supported video type.
- `IRPlayerImp` reduced to public API translation and composition over
  presentation, environment, media, settings, backend, and event owners.
- Serialized backend replacement transactions that stop the previous backend
  before source/input mutation and reject inactive-backend events.
- Explicit presentation ownership of the display view, render selection,
  gravity, gesture, smooth-scroll, sensor, tap, snapshot, and teardown paths.
- Exact application observer and audio-handler ownership with synchronized
  lifecycle decisions, safe manager replacement, and injectable idle timer.
- Synchronized facade settings/media state, deterministic invalid-load and
  backend-unavailable cleanup, and one final stop transition.
- Reentrant-safe serial render execution shared by viewport, mode,
  interaction, frame, surface, clear, reset, and close operations.
- Complete-or-unavailable Metal surface generations with explicit failure
  phases, retry, coherent diagnostics, and terminal teardown.
- Dedicated frame-submission ownership of current frame/image, redraw,
  dimensions, render completion, and real black-buffer clearing.
- Coalesced snapshot generations that schedule only after a completed render
  and cancel pending or scheduled stale work during close.
- Main-thread AVPlayer-layer attachment, reuse, gravity, layout, detachment,
  and terminal close isolated from Metal lifetime.
- `IRGLView` reduced to UIKit/API translation over render, snapshot, and
  AVPlayer-layer owners, with render-to-main lock inversion removed.
- Render strategies moved out of `IRGLView`, with `IRGLViewPolicy` and
  `IRGLRenderStrategyPolicy` decisions consolidated into their domain owners.
- Fish2pano lookup maps are built as immutable generations, atomically
  published, and retained independently while the renderer consumes them.
- VideoToolbox hardware-decode setup now publishes complete resource
  generations behind explicit idle/setup/active/reset/close phases.
- VideoToolbox setup, decode, reset, and close share one serialized operation
  gate; reset is repeatable and close is terminal.
- VideoToolbox callback contexts are retained per resource generation, store
  coherent results, and are released only after leases drain, frames finish,
  and the decompression session is invalidated.
- Stale VideoToolbox setup tickets cannot publish after reset or close, and
  partial setup failures leave no installed resource.
- H.264/AVCC/NAL payload behavior is consolidated beside the VideoToolbox
  domain; `IRFFVideoToolBoxPolicy` and its facade forwarding layer are removed.
- FFmpeg input discovery and codec setup now build a complete local resource
  generation and publish it atomically only when at least one usable track
  opens.
- Format setup, read, seek, track replacement, and destroy share one serialized
  operation boundary; destroy requests interruption before waiting and closed
  is terminal.
- FFmpeg input callbacks use a separately retained synchronized interrupt
  context rather than an unretained format facade.
- Every allocated audio/video codec context is released with
  `avcodec_free_context`, including track replacement and terminal teardown;
  input close completes before callback-reference release.
- Format construction, resources, lifecycle facade, and pure semantics are
  separated by responsibility; `IRFFFormatContextPolicy` and forwarding
  wrappers are removed.

## Remaining Architecture Priorities

### 1. Whole-Tree Runtime Ownership Audit

The previously named `IRFFPlayer` owner gap is closed. The next audit must
inventory the remaining first-party Swift, Objective-C, C, and Metal types,
classify large mutable/resource-owning types, and verify that each lifecycle
boundary is explicit or deliberately documented. Absence of another named
owner in this document is not evidence that the whole-project audit is
complete.

Each split requires focused behavior tests before changing ownership.

### 2. Policy Consolidation

The source tree still contains many `*Policy.swift` helpers. New one-function
policy files remain prohibited. Existing helpers should move into the domain
state, value, or resource owner only when the associated runtime boundary is
being changed and covered.

### 3. Verification Expansion

- Run Thread Sanitizer on each newly changed concurrent boundary.
- Add close/reopen, cancellation, and resource-failure tests around backend
  owners.
- Keep the full simulator suite and generic device build as mandatory gates for
  every focused commit.

## Completion Rule

The whole-project 2.0 modernization is complete only after all remaining
runtime owners above have explicit lifecycle boundaries, their behavior and
failure paths have tests, the policy inventory has been reviewed, and the full
validation gates remain green.
