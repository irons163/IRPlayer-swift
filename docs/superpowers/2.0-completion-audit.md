# IRPlayer 2.0 Completion Audit

Updated: 2026-07-24

## Current Status

The public 2.0 playback architecture, typed events, serialized backend
coordinator, player facade runtime owners, render-state boundaries, decoder
runtime-state hardening, FFmpeg session resource ownership, AVFoundation
session ownership, and Core Audio output session ownership are implemented
and verified. The display runtime now also has explicit render-executor,
Metal-surface, frame-submission, snapshot, and AVPlayer-layer owners. FFmpeg
decoded-audio consumption is isolated from the player facade. The FFmpeg
backend now has a serialized runtime, explicit state and decoder-generation
owners, exactly-once generation-fenced seeks, coherent snapshots, and an
isolated main-thread presentation adapter. Projection meshes are now immutable
complete generations with checked construction, thread-safe VR sharing, and
atomic equirectangular replacement. Decoded PCM frames now own managed
contiguous storage behind scoped mutation and checked real-time copies, with no
escaping frame-owned sample pointer. Software-decoded I420 frames now publish
checked, Swift-managed copy-on-write plane generations consumed through scoped
snapshot bytes. FFmpeg option dictionaries now have one automatic owner,
borrowed dictionary conversion is non-owning, and parsed metadata is an
immutable value. Demuxed FFmpeg packets now have one automatic owner from read
through audio consumption or cross-thread video decode, with typed queue
control states. Decoder scratch frames and audio resampling now also have
automatic owners with scoped borrows and managed sample storage. The repository
now also isolates YUV snapshot scaling behind one automatic context owner,
Swift-managed RGB24 storage, and an exact scoped output boundary. It is
now also impossible for Core Video-backed Metal textures to outlive their
wrappers prematurely: immutable frame-texture generations retain every
`CVMetalTexture` and source pixel buffer, while per-command resource scopes
reuse a generation within multi-view work and transfer ownership through GPU
completion. Core Motion input now crosses an injectable immutable-value driver
boundary into one locked, generation-fenced session; stop, restart, orientation
changes, and main-thread delivery reject stale work deterministically.
Smooth-scroll animation now also has an injectable display-link owner and one
locked generation state: idle controllers no longer wake every frame, stale
ticks are inert, and gesture deceleration owns the exact motion-stop/restart
window. Decoded frames now cross one synchronized transport boundary with
coherent metadata snapshots, exact identity-owned pooling, immutable queue
accounting, condition-based wakeups, and terminal decoder teardown.
AVPlayer VR presentation now also owns an explicit session-token-bound
generation loop over the same reusable native display-link driver: normal
playback, reset, and failure are idle; replacement and teardown revoke stale
ticks before resource detachment; and terminal close invalidates the native
resource without retaining the backend. Metal renderer bootstrap now publishes
one immutable complete resource generation, surface and renderer work share one
command queue, and distortion render targets have one synchronized coherent
lifecycle owner. Video dimensions now publish as checked atomic values sourced
from their owning Core Video, I420, or RGB content. Custom RGB input now
publishes one immutable, format-explicit generation whose validated source
bytes drive both UIKit and Metal, while pooled I420 reuse revokes its prior
active generation without discarding capacity. Custom video decoding now also
crosses a pointer-free immutable value boundary: codec configuration,
extradata, compressed payload, timing, flags, and packet side data remain valid
for asynchronous work after FFmpeg packet/context teardown. Custom source and
output bindings are synchronized, weak, and explicitly revoked with their
decoder generation. Decoder delegate, custom source, video output, and audio
output now form one weak `IRFFDecoderCollaboratorSession` generation installed
before open and revoked atomically before teardown. Video delivery is ordered
against revocation, delegate/audio access uses deadlock-safe strong snapshots,
child source installation cannot race detachment, and direct decoder close
cannot resurrect bindings. Photo-library saves now also cross a value-only
driver boundary into one locked transaction session with explicit request
stages, exactly-once terminal outcomes, coalesced same-album creation,
duplicate/stale callback rejection, and deterministic close. Photos framework
objects remain isolated in the system driver, and the forwarding-only photo
policy has been removed. Process-wide logging configuration now also belongs
to one synchronized `IRPlayerLoggingSession`: delegate ownership is weak
between emissions and strongly snapshotted per callback, configuration
generations publish coherent subsystem/logger pairs, close is terminal, and no
external sink runs under the owner lock. Public logger accessors remain
source-compatible, while FFmpeg and Metal diagnostics use the public logging
boundary and three forwarding-only logging policies have been removed. It is
releasable at each completed slice, but the whole-project modernization
requested for 2.0 is not yet complete.

## Remaining Architecture Priorities

### 1. Whole-Tree Runtime Ownership Audit

The previously named `IRFFPlayer`, format-context, VideoToolbox, projection,
decoded-audio-frame, software-YUV-plane, YUV-image-conversion,
FFmpeg-dictionary, FFmpeg-packet, decoder-scratch, and Metal command-texture
owner gaps are closed. The fish2pano managed lookup-generation boundary is also
closed, as are the sensor motion-session and smooth-scroll display-link/session
owners, the decoded-frame pool/queue transport boundary, and the AVPlayer
presentation-loop/shared native display-link boundary. Metal renderer
bootstrap, shared surface command-queue ownership, and distortion-target
generation ownership are now closed as well. Atomic video geometry, immutable
custom RGB generations, and I420 reuse revocation are now closed as well.
Pointer-free custom video decode values and synchronized source/output
bindings are now closed as well. Atomic whole-decoder collaborator
installation, delivery ordering, direct-close revocation, and player
generation teardown are now closed as well. Photo-library transaction
ownership, same-album creation coalescing, and callback fencing are now closed
as well. Process-wide logging configuration, delegate delivery, reentrancy,
terminal close, and FFmpeg/Metal diagnostic routing are now closed as well.
The next audit must
continue through the remaining first-party Swift, Objective-C, C, and Metal
types, classify large mutable/resource-owning types, and verify that each
lifecycle boundary is explicit or deliberately documented. Absence of another
named owner in this document is not evidence that the whole-project audit is
complete.

Each split requires focused behavior tests before changing ownership.

### 2. Policy Consolidation

The source tree now contains 33 `*Policy.swift` helpers after the three
forwarding-only logging policies were removed. New one-function policy files
remain prohibited. Existing helpers should move into the domain state, value,
or resource owner only when the associated runtime boundary is being changed
and covered.

### 3. Verification Expansion

- Run Thread Sanitizer on each newly changed concurrent boundary.
- Add close/reopen, cancellation, and resource-failure tests around backend
  owners.
- Keep the full simulator suite and generic device build as mandatory gates for
  every focused commit.
