# IRPlayer 2.0 Completion Audit

Updated: 2026-07-23

## Current Status

The public 2.0 playback architecture, typed events, backend coordinator,
render-state boundaries, decoder runtime-state hardening, FFmpeg session
resource ownership, and AVFoundation session ownership are implemented and
verified. The repository is releasable at each completed slice, but the
whole-project modernization requested for 2.0 is not yet complete.

Current validation:

- iOS Simulator: 969 passed, 0 failed, 0 skipped.
- Thread Sanitizer focused FFmpeg decoder/state/queue suites: 89 passed, 0
  failed.
- Thread Sanitizer focused AVPlayer/session suites: 75 passed, 0 failed, no
  race diagnostics.
- Generic iOS device build: passed.
- Remaining compiler warnings originate in bundled FFmpeg headers.

## Completed Boundaries

- Typed media source, configuration, playback events, and observation tokens.
- Backend protocol and coordinator separating the facade from AVFoundation and
  FFmpeg implementations.
- Explicit player lifecycle state.
- Render state/coordinator and render-mode configuration extraction.
- FFmpeg read/display decision helpers.
- Synchronized FFmpeg decoder session state with atomic seek and idempotent
  close semantics.
- Thread-safe FFmpeg bootstrap, packet/frame queue accounting, and video-decoder
  worker state.
- Explicit FFmpeg decoder-session ownership of operations, format context, and
  audio/video decoders, including resource leases and deterministic teardown.
- Duplicate/post-close open rejection and opening-phase resource publication
  fencing.
- Explicit AVFoundation session ownership of the asset, item, player, output,
  observations, notification, and periodic-time token.
- AVFoundation generation tokens and resource leases that reject stale asset,
  seek, retry, observation, and output work across replacement.
- Silent AVFoundation close and deterministic repeatable reset.
- Real `AVPlayerLayer` attachment for normal playback, with VR isolated to the
  video-output/display-link/Metal presentation path.
- AVPlayer command, lifecycle, presentation, track, and resource-owner
  responsibilities split into focused implementation files.

## Remaining Architecture Priorities

### 1. Remaining Large Runtime Facades

The next audit should split responsibilities in this order:

1. `IRAudioManager` audio-session and render-resource ownership.
2. `IRPlayerImp` rendering/interaction facade responsibilities.
3. `IRGLView` surface, gesture, snapshot, and frame-submission responsibilities.
4. `IRFFPlayer` adapter and audio-output lifecycle.

Each split requires focused behavior tests before changing ownership.

### 2. Policy Consolidation

The source tree still contains many `*Policy.swift` helpers. New one-function
policy files remain prohibited. Existing helpers should move into the domain
state, value, or resource owner only when the associated runtime boundary is
being changed and covered.

### 3. Verification Expansion

- Run Thread Sanitizer on each newly changed concurrent boundary.
- Add close/reopen, cancellation, and resource-failure tests around backend
  owners.
- Keep the full simulator suite and generic device build as mandatory gates for
  every focused commit.

## Completion Rule

The whole-project 2.0 modernization is complete only after all remaining
runtime owners above have explicit lifecycle boundaries, their behavior and
failure paths have tests, the policy inventory has been reviewed, and the full
validation gates remain green.
